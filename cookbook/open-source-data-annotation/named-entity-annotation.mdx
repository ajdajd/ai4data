# 2. Named entity annotation

**Question:** How can entity mentions in text be marked and reviewed?

## Rationale

Named entity annotation marks the words that refer to people, places,
organizations, or other entities defined for the task. A span is a continuous
selection of characters with a start position, an end position, and an
annotation label.

Doccano provides a sequence-labeling project for this task. It keeps the
passage and the selected character positions together in its native export.
These reviewed examples can support data curation, extraction-system
development, or quality assurance. This chapter teaches annotation and export;
it does not require a model or the other chapters.

## Target state

- Every imported passage retains a stable source identifier and unchanged text.
- Entity spans follow written labeling rules and have been reviewed.
- The native JSONL export reconstructs the intended text from every span.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | A person marks entity mentions and checks the selected text in the export. |
| **AI-ready** | Stable identifiers and validated offsets make the labels reusable by software. |
| **AI-native** | A model could propose spans for human correction with provenance retained. This extension is reserved for Pass 2. |

:::info[Running example]
The exercise reuses 14 fictional sentences from the
[Monitoring of Data Use cookbook](/cookbook/monitoring-data-use/detect).
The task is to mark references to data sources in twelve sentences and review
two sentences that have no mentions to label.
:::

## Recipes

<Recipe title="2.1 Set up a dataset-mention project" level="Foundational" skills="Data practitioner comfortable with a terminal and a browser" time="Thirty minutes, plus dependency download time">

**Result:** Doccano contains a sequence-labeling project with 14 unchanged sentences and one DATASET label.

Doccano uses a web application for labeling and a worker for imports and
exports. Both must remain running while completing the exercise.

### Set up the dependencies

1. Create a working directory with folders for the input passages and exported
   annotations, then enter it.

```shell
mkdir -p annotation-entities/input annotation-entities/output
cd annotation-entities
```

2. Download [passages.jsonl](pathname:///cookbook-files/open-source-data-annotation/passages.jsonl)
   into `input`. Download
   [requirements-doccano.txt](pathname:///cookbook-files/open-source-data-annotation/requirements-doccano.txt)
   and [inspect_doccano.py](pathname:///cookbook-files/open-source-data-annotation/inspect_doccano.py)
   into the working directory. JSONL stores one JSON object per line.
   Inspect the UTF-8 input before importing it; each record has these fields.

| Field | Meaning |
|---|---|
| `source_id` | This stable identifier distinguishes a passage, even when passages repeat a dataset name. |
| `document_id` | This field preserves the source sample's document identifier, D01–D06. |
| `text` | This exact text is displayed and labeled. |
| `label` | The empty list supplies the native annotation field without revealing any answers. |

The input contains 14 records, identified as `m01`–`m14`. Each starts with
an empty `label` list so that annotation begins without suggested answers.

```json file=../../website/static/cookbook-files/open-source-data-annotation/passages.jsonl
```

3. Create an isolated Python 3.10 environment and install the supplied
   dependencies, including doccano 1.8.4. The `--override` option applies the
   compatibility versions in the requirements file. For platform-specific
   installation help, see the
   [official installation guide](https://doccano.github.io/doccano/install_and_upgrade_doccano/).

```shell
python3.10 -m venv .venv-doccano
source .venv-doccano/bin/activate
python -m pip install uv
uv pip install --python python -r requirements-doccano.txt --override requirements-doccano.txt
```

### Configure doccano

4. Create `.env` to set the local database and upload directory. Change
   `doccano-state` here to store the application state elsewhere.

```shell
cat > .env <<EOF
DOCCANO_HOME="$PWD/doccano-state"
EOF
```

5. Initialize the database and create the `annotator` account. Choose a password
   when prompted. These credentials are only for this local doccano instance.

```shell
dotenv -f .env run --no-override -- doccano init
read -rsp "Local annotator password: " DOCCANO_PASSWORD
dotenv -f .env run --no-override -- \
  doccano createuser --username annotator --password "$DOCCANO_PASSWORD"
unset DOCCANO_PASSWORD
```

6. Start the web application in this terminal.

```shell
dotenv -f .env run --no-override -- doccano webserver --port 8000 --workers 1
```

   In a second terminal, enter `annotation-entities`, activate the environment,
   and start the import/export worker. Leave both terminals running.

```shell
source .venv-doccano/bin/activate
dotenv -f .env run --no-override -- doccano task --concurrency 1
```

7. Open [http://127.0.0.1:8000](http://127.0.0.1:8000) and log in as `annotator`
   with the password from Step 5. On the project list, click **Create**.
   Name the project `Data Use sentence annotation` and choose
   **Sequence Labeling**. Leave overlapping entities, grapheme mode, and
   relation annotation disabled, then save the project. Open **Labels** in the
   project menu and add `DATASET`. For another use case, choose the label names
   that describe the entities to mark.
8. Open **Dataset → Actions → Import Dataset**. Choose **JSONL** and select
   `input/passages.jsonl`. Set the text column to `text` and the label column
   to `label`, then import the file. Expect 14 records. Click
   **Start annotation** to open the first sentence. Its metadata should include
   `source_id: m01`, and the label list should offer `DATASET`.

**Worked example.** Record `m01` contains “We use the Household Budget
Survey 2021 to estimate consumption per adult equivalent.” Record `m14`
contains “The outlook covers twelve countries in the region.” Importing
`input/passages.jsonl` puts both in the project without highlighted words,
ready for annotation.

**What this does not do.** This local setup does not configure a shared
production service, OCR, or PDF text extraction. The passages are prepared
inputs. The application must not transform them after span positions are set.

</Recipe>

<Recipe title="2.2 Label dataset mentions" level="Foundational" skills="Data curator or research annotator" time="Twenty minutes">

**Result:** Each passage has reviewed entity labels or an explicit review decision that no dataset is mentioned.

For this exercise, `DATASET` marks a specific source of data: a survey,
census, indicator series, or report. The source may be named or described.
A generic phrase such as “a food security report” receives no label.

1. In the annotation interface, find `source_id: m01` in the record metadata.
   Drag across `Household Budget Survey 2021` in the sentence, then choose
   `DATASET` from the label menu. The selected words should appear highlighted.
   Click the review indicator (initially **×**) in the annotation toolbar.
   It should change to **✓**, marking the sentence as reviewed.
2. In `m02`, label `HBS`. In `m08`, select the entire phrase
   `Household Budget Survey (HBS) 2021` as one span. Confirm both sentences.
3. Use the navigation arrows to review the remaining references in `m03`–`m12`.
   Confirm each sentence after labeling it. The sample includes
   the descriptive phrase `The labour survey` in `m07` and a report cited as
   a data source in `m04`.
4. Read `m13` and `m14` and leave them without highlighted words. Click the
   review indicator so that it shows **✓** for each. This records a reviewed
   sentence with no specific data-source mention.
5. To correct a selection, right-click its highlighted words to remove it,
   then select the intended words and apply `DATASET` again. Check that the
   review indicator shows **✓**, navigate away, and return to check that the
   corrected highlight remains saved.

**Worked example.** The intended selection in `m01` is
`Household Budget Survey 2021`. After labeling and confirming all 14 sentences,
the example has 12 highlighted mentions. Records `m13` and `m14` are confirmed
without highlights.

**What this does not do.** This exercise does not resolve every descriptive
or vague reference in research literature. Difficult cases need a documented
annotation decision and possibly a second reviewer. Repeated names at
different positions remain separate mentions.

</Recipe>

<Recipe title="2.3 Export and verify native entity spans" level="AI-ready" skills="Data curator; basic Python use" time="Fifteen minutes">

**Result:** A native doccano JSONL export preserves the original passages and reconstructs every selected mention.

The export stores selected words as character positions, called offsets.
The inspection script displays the words at those positions and checks that
the exported sentences still match the input.

1. Use **Actions → Export Dataset**, choose ordinary sequence-labeling
   **JSONL**, and include the complete reviewed set. Extract the download
   archive if necessary. Save the annotator's JSONL in `output` as
   `entities-export.jsonl`. Keep the native file unchanged, including its metadata.
2. In a terminal in `annotation-entities`, run the inspection script. It prints
   each selected phrase on its own line for easier inspection.

```shell
python inspect_doccano.py entities output/entities-export.jsonl \
  --source input/passages.jsonl
```

The supplied [example export](pathname:///cookbook-files/open-source-data-annotation/entities-export.jsonl)
shows the expected annotations. With the same selections, the command prints:

```text
m01 [11:39] 'Household Budget Survey 2021'
m02 [4:7] 'HBS'
m03 [47:84] 'prevalence of undernourishment series'
m04 [7:59] 'National Statistics Office food security report 2025'
m05 [28:80] 'Prevalence of undernourishment (FS_UNDERNOURISH_PCT)'
m06 [17:36] 'Labour Force Survey'
m07 [0:17] 'The labour survey'
m08 [15:49] 'Household Budget Survey (HBS) 2021'
m09 [38:72] 'Demographic and Health Survey 2016'
m10 [28:62] 'Population and Housing Census 2014'
m11 [4:34] 'unemployment rate from the LFS'
m12 [33:61] 'World Development Indicators'
PASS: 14 unchanged record(s); 12 span(s).
```

The first path selects the export to inspect; `--source` selects the original
input. Change these paths when using other files. The script rejects changed
text, missing or duplicate source identifiers, invalid offsets, unknown labels,
and overlapping spans.

3. Compare the displayed phrases with the highlights saved in doccano.
   Open `output/entities-export.jsonl` in a text editor to inspect a record's
   fields. Keep `input/passages.jsonl` with the export so that its offsets can
   always be checked against the original text.

| Field | What to inspect |
|---|---|
| `source_id` | The identifier connects each annotation to its input sentence, regardless of the tool's internal record ID. |
| `text` | The sentence must match the input exactly. |
| `label` | Each selection has the form `[start, end, "DATASET"]`. The start is included and the end is excluded. Positions count Unicode characters. |

**Worked example.** A native label triple `[11, 39, "DATASET"]` for `m01`
reconstructs `Household Budget Survey 2021`, the phrase selected in Recipe 2.2.
The export contains the same 14 source identifiers, including `m13` and `m14`
with no entity labels.

**What this does not do.** Valid offsets can still select the wrong words.
An empty label list does not prove that a person reviewed the record. The
validator does not normalize text, align changed versions, or measure model
quality. Relation-enabled exports are outside this introductory format.

</Recipe>

## Common mistakes

- Editing imported text after annotation changes the reference for its character positions.
- Treating generic data nouns as named datasets changes the agreed inclusion policy.
- Deduplicating repeated names removes separate mention positions that the annotation task needs.
- Replacing source identifiers with internal project IDs breaks the connection to the original passages.

## Verification

- Confirm that all 14 source records survive import and export with unchanged text.
- Read the reconstructed spans and compare them with the labeling rules.
- Check a reviewed negative separately from an unfinished record in the UI.
- For the Unicode examples, reopen the saved records and compare the browser highlights with `text[start:end]` in the export.

The additional Unicode checks concern how software counts characters. The
validator uses Python Unicode code points, with an exclusive end position.
Grapheme mode groups displayed characters differently, which is why it remains
disabled in the example project. Changing whitespace, line endings, accents,
or Unicode normalization after labeling can move offsets.

The optional [unicode-passages.jsonl](pathname:///cookbook-files/open-source-data-annotation/unicode-passages.jsonl)
contains two practice passages, `p06` and `p07`. They preserve composed
and combining accents, a leading emoji, and a newline. Download it into
`input`. Import these two records into a separate sequence-labeling project
with the same settings.
Label exactly `Labour Force Survey` in each, confirm both records, and export
to `output/unicode-export.jsonl`. Then run from `annotation-entities`:

```shell
python inspect_doccano.py entities output/unicode-export.jsonl \
  --source input/unicode-passages.jsonl
```

Use the [Unicode example export](pathname:///cookbook-files/open-source-data-annotation/unicode-export.jsonl)
to inspect the expected offsets. Compare the browser's saved highlights with
`text[start:end]` in the export. Keep the source text unchanged.
