# 1. Bounding-box annotation

**Question:** How can figures and tables in PDF documents become reviewed spatial annotations?

## Rationale

Data annotation assigns labels to records or regions that a person can inspect.
An image bounding box locates a region on a rendered PDF page, and its
annotation label identifies the kind of content. A collection of labeled
boxes can support document indexing, data curation, or later work with an
extraction system.

Label Studio is an open-source tool for labeling data through a browser.
For this task, it displays rendered PDF pages so that an annotator can draw
rectangles and assign labels without changing the source PDF. This chapter
starts with blank tasks and ends with native Label Studio JSON. No detection
model or metadata extraction is required.

## Target state

- Each input PDF has one Label Studio task whose page images follow the PDF page order.
- Figure and table boxes use the intended labels and have been submitted.
- The native export preserves the source filename, page association, and labels.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | A person labels figures and tables and retains the submitted native export. |
| **AI-ready** | The organization documents labels, page identity, and coordinate units so that software can interpret the export. |
| **AI-native** | Model suggestions could be reviewed with their provenance and verification retained. That optional extension is outside this pass. |

:::info[Running example]
This exercise reuses the sample publication from the
[Data Snapshot cookbook](/cookbook/data-snapshot-end-to-end/preparation),
*From Stateless to Citizens: The Journey of Shona in Kenya*. The PDF has
12 pages. PDF page 4 contains Figure 1 on labor-force status and Table 1 on
demographic characteristics. The exercise labels those two regions while
keeping the full document together in one task.
:::

## Recipes

<Recipe title="1.1 Create a multipage PDF project" level="Foundational" skills="Developer or data curator comfortable with a terminal" time="Thirty minutes, plus dependency download time">

**Result:** Label Studio contains one task for the example PDF, with all 12 page images available for annotation.

A Label Studio project contains the documents to annotate and the available
labels. This recipe creates one task per PDF, with its pages displayed as
images for labeling.

The commands below use a Linux or macOS shell and Python 3.10 in a separate
environment. Windows readers can use WSL or adapt environment activation using
the [official installation guide](https://labelstud.io/guide/install).
The local media root must be the same absolute directory in the server and
the script.

Steps 1–4 prepare the files, Python environment, and dependencies. Steps 5–9
configure Label Studio and create the annotation project.

### Files and dependencies

1. Create a working directory named `annotation-pdf` and an `input/`
   subdirectory inside it. Use `annotation-pdf` as the working directory
   for subsequent steps.
   Keep source PDFs in `input/` so that they are separate from the scripts,
   application database, and generated page images.

The following commands create both directories and enter the working directory.

```shell
mkdir -p annotation-pdf/input
cd annotation-pdf
```

2. Download [create_pdf_project.py](pathname:///cookbook-files/open-source-data-annotation/create_pdf_project.py)
   and [multipage-labels.xml](pathname:///cookbook-files/open-source-data-annotation/multipage-labels.xml)
   into `annotation-pdf`. Keep the XML beside the script because it defines
   the labeling interface.
3. Obtain the PDF from the
   [ReliefWeb publication page](https://reliefweb.int/report/kenya/policy-brief-stateless-citizens-journey-shona-community-kenya)
   or its [PDF attachment](https://reliefweb.int/attachments/831aca28-6777-4cb9-9b84-8976c63061fb/Policy%20Brief%20on%20Shona%20community_From%20Stateless%20to%20Citizens.pdf).
   Save it in `annotation-pdf/input/` as
   `policy_brief_on_shona_community_from_stateless_to_citizens.pdf`.
   Confirm that it has 12 pages and that PDF page 4 contains Figure 1 and
   Table 1. That directory should contain only this PDF for the worked
   example.
4. Create an isolated Python environment, activate it, and install Label
   Studio and the required packages.

The commands below install Label Studio and the PDF setup dependencies.

```shell
python3.10 -m venv .venv-labelstudio
source .venv-labelstudio/bin/activate
python -m pip install "label-studio==1.22.0" "pymupdf==1.28.2" "requests==2.32.5" "python-dotenv[cli]>=1,<2"
```

### Label Studio configuration and project creation

5. Create separate directories for Label Studio's database and rendered
   images, then create `.env` with the configuration below. `ls-state`
   holds the database; `ls-media` holds the page images served to the
   browser. Leave `LABEL_STUDIO_API_KEY` empty until Step 7.

Keep this local `.env` file out of version control.

```shell
mkdir -p ls-state ls-media
cat > .env <<EOF
LABEL_STUDIO_BASE_DATA_DIR="$PWD/ls-state"
LABEL_STUDIO_LOCAL_FILES_DOCUMENT_ROOT="$PWD/ls-media"
LABEL_STUDIO_LOCAL_FILES_SERVING_ENABLED=true
LABEL_STUDIO_API_KEY=
EOF
chmod 600 .env
```

Start Label Studio and leave this terminal running.

```shell
dotenv -f .env run --no-override -- label-studio start --port 8080 --internal-host 127.0.0.1 --no-browser --enable-legacy-api-token
```

6. Open a second terminal in `annotation-pdf` and initialize a local account.
   Enter an email address when prompted and set
   the account password at the initialization prompt. Use this account to
   sign in when opening the project in Step 9.

These login details are only for the local Label Studio instance used for
offline annotation.

Activate the environment and create the account with the following commands.

```shell
source .venv-labelstudio/bin/activate
read -rp "Local account email: " LABEL_STUDIO_USERNAME
dotenv -f .env run --no-override -- label-studio init --username "$LABEL_STUDIO_USERNAME" --enable-legacy-api-token
```

7. In the second terminal, retrieve the account's legacy API token and
   save it in `.env`.

Run the following command to display the token.

```shell
dotenv -f .env run --no-override -- \
  label-studio user --username "$LABEL_STUDIO_USERNAME" \
  | grep -o "'token': '[^']*'"
```

The output has the following form. `<legacy-token>` represents
the generated token; copy the value inside its quotes.

```text
'token': '<legacy-token>'
```

Edit `.env` in `annotation-pdf` and replace the empty `LABEL_STUDIO_API_KEY`
value with the copied token. After editing, the API-key line should look like this, with the placeholder
replaced by the actual key.

```text
LABEL_STUDIO_API_KEY="paste-your-legacy-token-here"
```

Save `.env` before proceeding.

8. Run the setup command below to create the project and import the PDF.

```shell
python create_pdf_project.py \
  --input-dir input \
  --data-root ls-media \
  --batch shona \
  --title "Shona policy brief"
```

| Parameter | Meaning |
|---|---|
| `--input-dir input` | The script reads PDFs from `input/` and its subdirectories. |
| `--data-root ls-media` | The script writes images under `ls-media/`. This must be the same directory configured in `.env`. |
| `--batch shona` | The script creates `ls-media/shona/` for the rendered images and `tasks.json`. An existing batch name is refused to preserve its files. |
| `--title "Shona policy brief"` | This name appears in Label Studio's project list. |

9. Open `http://127.0.0.1:8080` in a browser and sign in with the account
   from Step 6. Under **Recent Projects**, open **Shona policy brief**.
   The project's Data Manager should show one row, corresponding to the
   single PDF imported in Step 8. Click that row to open the annotation
   interface and confirm that all 12 page images load in order. If images
   do not load, check that the media directory in `.env` matches `--data-root`.

The supplied `multipage-labels.xml` file preconfigures the project with two
labels: **Figure** and **Table**. Labels can be changed under
**Settings → Labeling Interface**, but customization is outside this tutorial.
For a walkthrough of multipage PDF annotation, see Label Studio's
[Paginated Multi-Image Labeling tutorial](https://labelstud.io/videos/announcing-paginated-multi-image-labeling/).

**Worked example.** With the policy brief in `input/`, the command creates
a project named `Shona policy brief` containing one task with 12 page images.
The images and task file are saved under `ls-media/shona/`. The regions on
PDF page 4 remain unlabeled until Recipe 1.2.

The terminal output follows this pattern. `<project-id>` and
`<working-directory>` represent values from the local installation.

```text
Created project <project-id>: 1 PDF task(s).
Rendered 12 page(s).
Tasks: <working-directory>/ls-media/shona/tasks.json
Open http://127.0.0.1:8080/projects/<project-id>/data
```

The same command processes multiple PDFs when they are placed in `input/`.
Batches of about 10–20 PDFs are a practical starting guideline, adjusted for length,
complexity, and available resources. This is not a technical limit.

**What this does not do.** The command does not label regions, run inference,
or back up the application database. A failed API request can leave rendered
files or a partial project. Inspect the reported project and choose a new
batch before retrying; the script does not delete partial work automatically.

</Recipe>

<Recipe title="1.2 Draw and submit figure and table boxes" level="Foundational" skills="Data curator or document annotator" time="Twenty minutes for the two regions on PDF page 4">

**Result:** The document task contains submitted rectangles labeled Figure and Table.

1. In the annotation interface, navigate to PDF page 4. Select **Figure**,
   then click and drag to draw a box around Figure 1.
2. Click a box to select it, then drag a corner or edge to resize it.
   To practice deleting, draw an extra box, select it, and press
   **Backspace** (**Delete** on a Mac).
3. Select **Table** and draw a box around Table 1 on the same page. If a
   box has the wrong label, select it and choose the correct label.
4. Continue to PDF pages 5–8 for optional practice with the additional
   figures. These pages can be left unannotated for this tutorial.
   Leave other pages without boxes if they are not being labeled.
5. Click **Submit** to save the annotations for the whole PDF. Pages without
   boxes remain unannotated; no separate submission is needed for each page.
   Reopen the task from the Data Manager and confirm that the boxes remain
   saved. Use **Update** to save any later edits.

**Worked example.** Drawing boxes around Figure 1 and Table 1 on PDF page 4,
then clicking **Submit**, saves one Figure box and one Table box for the PDF.
Labeling the optional pages adds more boxes to the same document task.

**What this does not do.** This exercise does not produce a complete
annotation of the publication. An unannotated page may still contain
figures or tables.

</Recipe>

<Recipe title="1.3 Export and inspect native annotations" level="AI-ready" skills="Data curator; basic JSON familiarity" time="Fifteen minutes">

**Result:** The organization retains a native Label Studio JSON export and can explain its page associations and coordinate units.

The native export is the primary output of this chapter. It preserves task
data and annotation results. An annotation result is a labeled region within
a submitted annotation. Predictions and unfinished drafts are separate from
submitted annotations and should not be silently treated as reviewed labels.

1. In the project page, select **Export** and choose **JSON**.
   Save the downloaded file in the working directory as `labelstudio-export.json`.
2. Run the following command to create an indented copy of the export.

```shell
python -m json.tool labelstudio-export.json labelstudio-export.pretty.json
```

3. Open `labelstudio-export.pretty.json` in a text editor.
   Use the editor's Find function to locate `"pages"` under `"data"` and
   `"source_file"` under `"meta"`. Confirm the source PDF and its 12 page
   images. Under `"annotations"`, inspect `"result"` for the Figure and Table
   entries on PDF page 4. Both should have `"item_index": 3`. Additional
   results appear if the optional pages were labeled. Use the submitted
   annotation and exclude drafts and predictions.
   Keep the source PDF, rendered images, and labeling configuration with
   the original export because an image address alone does not embed the image bytes.

| Field | Meaning |
|---|---|
| `from_name` / `to_name` | These fields connect `rectangles` to the configured image object `pdf`. |
| `item_index` | This zero-based index associates a result with an entry in `data.pages`; PDF page 1 has index 0. |
| `original_width` / `original_height` | These fields describe the original rendered image dimensions in pixels. |
| `value.rectanglelabels` | This list contains `Figure` or `Table`. |
| `value.x` / `value.y` | These values locate the top-left corner as percentages of image width and height. |
| `value.width` / `value.height` | These values give the rectangle size in the same percentage units. |
| `value.rotation` | This value records rectangle rotation, which this workflow keeps at zero. |

**Worked example.** The supplied
[example export](pathname:///cookbook-files/open-source-data-annotation/labelstudio-export.json)
contains a Figure result and a Table result with `item_index: 3`, the fourth
entry in `data.pages`. Its `meta.source_file` retains the publisher's original
download filename.

The native Label Studio JSON remains the annotation record. When a downstream
application requires another representation, a format-conversion adapter
transforms the export, including the required label, coordinate, image-identity,
and annotation-status mappings. [COCO](https://cocodataset.org/#format-data)
is a widely used computer-vision format that can serve as such a destination.
The receiving application's requirements determine the format to use.

The World Bank
[Data Snapshot dataset](https://huggingface.co/datasets/ai4data/data-snapshot)
provides an example of a project-specific destination: its custom unified
evaluation schema records document/page identity and normalized boxes in a
shared representation for ground truth and detector predictions. In the
benchmarking workflow, model-specific format-conversion adapters translate each
detector's output into that common contract.

**What this does not do.** An export does not certify annotation quality or
include every source file. The recipe does not convert exports to COCO or
the Data Snapshot evaluation schema. A destination schema must be chosen
for the actual downstream task before conversion is implemented.

</Recipe>

## Implementation options

- The standalone script and local installation keep the multipage workflow within one command after setup.
- The official Docker installation is an alternative when container paths and persistent storage are configured consistently.
- Tool-native JSON preserves the annotation record; a downstream adapter can be added when a specific application requires one.

## Common mistakes

- A different media root in the server and script produces image addresses that the server cannot resolve.
- A rectangle is left with the wrong label after editing.
- A saved draft is mistaken for a submitted annotation.
- A percentage width is interpreted as a right-edge coordinate or a pixel count.

## Verification

- Confirm that the example PDF creates one task containing 12 ordered page images.
- Confirm that the submitted results contain a Figure and a Table, both on page index 3.
- Compare each exported rectangle with its displayed page and check its label and percentage units.
- Correct a rectangle, submit the task, reopen it, and confirm that the saved change appears in the export.
