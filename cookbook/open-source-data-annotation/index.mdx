# Practical Guide to Open-Source Data Annotation Tools

**A cookbook for data practitioners and statistical data curators.** Version 0.1 (working draft), November 2026.

:::note[Working draft]
This guide is a working draft from the AI for Data – Data for AI program.
It provides practical examples and does not represent official World Bank
Group guidance or policy. Its [contributing page](./contributing.md) explains
how to propose corrections. The cookbook remains hidden during editorial
review. Hidden production builds omit downloadable assets; a local development
preview or repository checkout is needed to review the complete workflows.
:::

Data annotation makes a person's interpretation explicit as a label attached
to a record or a selected region. The result may support data curation,
statistical processing, model development, evaluation, or other applications.
The immediate task is to prepare appropriate inputs, apply consistent labels,
and obtain outputs whose meaning can be checked.

This guide covers three tasks: figure/table bounding boxes with Label Studio,
dataset-mention spans with doccano, and occupation-response categories with
doccano. Each chapter contains its own setup, annotation, and export path.
Readers can start with whichever chapter matches their task. No chapter is
a prerequisite for another, and none requires model inference.

The examples use native tool formats, JSON/JSONL, and a small subset of
ISCO-08 for occupation coding. The [standards page](./standards.md)
distinguishes formal standards from application-specific representations.
Written labeling rules accompany each task so that syntactically valid
exports can also be reviewed for their intended meaning.

## Prerequisites

- A data practitioner or statistical data curator can use a browser and run the chapter's shell commands with Python 3.10 in an isolated environment.
- The machine can install the selected annotation tool, retain its local database, and store the example files and rendered images.
- An annotator understands the task's inclusion rules; a coding supervisor can resolve occupation responses that lack enough detail.
- Software reuse at the AI-ready level requires checking source identifiers, labels, and coordinate or character units. AI-native extensions require additional provenance and verification and are outside this pass.

The commands assume a local exercise on Linux or a compatible shell such as
WSL. Each chapter links official platform alternatives. Local services and
state should be kept separate from other projects. Installation and browser
verification limits are recorded in
[verification.md](pathname:///cookbook-files/open-source-data-annotation/verification.md).

## First steps

1. Select the matching task in the chapter table. Allow about five minutes
   to inspect that chapter's input and labeling rules.
2. Complete its first recipe to install the tool and prepare the project.
   Allow thirty minutes plus dependency download time.
3. Complete its manual labeling recipe, then export and inspect the output.
   Allow about thirty-five minutes for the small example.

After a successful export, the related resources explain downstream use.
Optional model-assisted annotation is reserved for a later pass.

## Maturity levels

The shared vocabulary describes organizational practice. A short tutorial
demonstrates a technique without establishing the maturity of an organization.

| Level | Meaning |
|---|---|
| **Foundational** | The practice exists in a form a person can use and a crawler can read. |
| **AI-ready** | The practice is structured, identified, and accessible through documented interfaces, so that software, including AI systems, can use it without manual steps. |
| **AI-native** | The practice offers AI-oriented interfaces or methods, with provenance and verification built in. |

## Running example

The National Statistics Office (example) produces a fictional Labour Force
Survey and a labour market report. This guide uses report `EX-REP-2025-02`
and survey round `EX-LFS-2025-Q2`, already identified in the shared
[example facts](pathname:///cookbook-files/_example/facts.json).

The original two-page PDF contains a chart and table of the example's
unemployment rates, 6.3% for 2025-Q1 and 6.1% for 2025-Q2. The latter is
provisional. Seven fictional research-style passages refer to example
datasets, and six fictional occupation responses illustrate coding decisions.
The six responses do not generate the national indicators and are not a
statistically meaningful sample. The files are related teaching materials,
not a claim that one annotation task produces another task's inputs.

The PDF is supplied ready to use. Its build script reads the shared facts
when rebuilding the file; the annotation workflow does not require rebuilding.
The [source notes](pathname:///cookbook-files/open-source-data-annotation/sources.md)
describe provenance, licensing, and the distinction between captured service
exports and actual human browser review.

## Scope of the examples

The examples are small on purpose. Each recipe names its limits and includes
an inspectable input, action, and intended or observed output. A structurally
valid export does not prove semantic correctness or reviewer agreement.
Pass 1 covers manual workflows only. It includes no model inference,
training, custom completion system, or downstream evaluation converter.
