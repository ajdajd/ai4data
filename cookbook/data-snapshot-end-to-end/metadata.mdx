# 4. Semantic metadata extraction

**Question:** How is a crop described in structured metadata?

## Rationale

The two crops selected in [chapter 3](./snapshots.mdx) are the inputs to the metadata stage. This stage uses a vision-language model, which processes an image together with text instructions. The production prompt asks for evidence visible in that image and excludes filenames and parent-document metadata. Its response is validated against the canonical Data Snapshot Metadata Schema v1.4 before a JSON file is saved.

Metadata fields describe analytical meaning: measured variables, their units, grouping dimensions, temporal coverage, visible sources, and related context. They do not hold a reconstructed numerical dataset. Missing and null fields represent unavailable information; validation cannot establish that the model interpreted the image correctly.

## Target state

- Exactly one selected figure and one selected table have corresponding metadata records.
- The reader can validate and interpret each record without treating it as transcribed data.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | A curator describes visible variables, units, groups, and missing context in notes alongside a crop. |
| **AI-ready** | The selected images receive schema-constrained model descriptions, and the raw JSON records are validated and interpreted separately from numerical observations. |
| **AI-native** | An organization integrates model-assisted metadata generation with validation and human review before reuse. Additional integration is needed to monitor semantic quality and manage corrections. |

:::info[Running example]
Only the chart `figure_001` and table `table_000` selected in chapter 3 are submitted for metadata extraction. Each has a corresponding raw JSON record. The figure response uses its vertical-axis label as the title, demonstrating why a schema-valid response still needs inspection.
:::

<Recipe title="4.1 Generate metadata for selected crops" level="AI-ready" skills="Developer and data curator" time="Ten minutes to select and submit the images; provider waiting time varies">

**Result:** Each selected image has one validated JSON record.

Using an individual image as input keeps the paid example bounded. The following two commands send the reviewed figure and table separately. The explicit output directory places their matching JSON files beside the snapshot directory. The remaining six candidate crops are outside this two-image request scope.

```bash
python -m ai4data.data_snapshot.extract_metadata \
  --input=output/cookbook-shona/doclayoutyolo/snapshots/policy_brief_on_shona_community_from_stateless_to_citizens_figure_001.png \
  --output-dir=output/cookbook-shona/doclayoutyolo/metadata \
  --metadata-provider=openrouter
```

```bash
python -m ai4data.data_snapshot.extract_metadata \
  --input=output/cookbook-shona/doclayoutyolo/snapshots/policy_brief_on_shona_community_from_stateless_to_citizens_table_000.png \
  --output-dir=output/cookbook-shona/doclayoutyolo/metadata \
  --metadata-provider=openrouter
```

1. Review the selected provider preset and key before running the commands.
2. Submit only the two selected crops. Passing the whole `snapshots` directory instead would process every discovered image, including the cover photograph.
3. Check that each JSON basename exactly matches its PNG basename. The final JSON contains the metadata record. API response details are available separately through the Python API.
4. Preserve the raw model records and keep human review notes separately.

**Worked example.** The downloadable figure and table JSON files are raw outputs from separate metadata-only requests on the actual DocLayout-YOLO crops. The combined command was not run. The review observations below describe their limitations; the raw JSON is unchanged.

**What this does not do.** Requests consume provider credits even when a result is unsuitable. No automatic retry or correction is applied. Existing JSON files are skipped without revalidation.

</Recipe>

1. Download the helper and selected JSON into the same working directory and run the command.
2. Inspect `variables` for measured concepts and units, `dimensions` for population groups or year columns, and `visualization_types` for the represented form.
3. Distinguish source wording in `source_text` from a controlled representation in `normalized_value`. A normalized interpretation must not be passed off as printed wording.
4. Open the full [figure JSON](pathname:///cookbook-files/data-snapshot-end-to-end/policy_brief_on_shona_community_from_stateless_to_citizens_figure_001.json) and [table JSON](pathname:///cookbook-files/data-snapshot-end-to-end/policy_brief_on_shona_community_from_stateless_to_citizens_table_000.json). Compare them with the actual crops and the [schema reference](/docs/data-snapshots/metadata-schema/).

**Worked example.** The figure record identifies employed and unemployed populations and the two population groups. Its `title` is `Percent of population`, which is visibly the vertical-axis label. The chart caption is outside the crop. The record can validate while this field remains questionable. The model's geographical coverage is null; the document's Kenya context was not provided as extra evidence.

The table's `title` is `null`, while its metadata identifies variables such as `Median age` and `Mean household size`, a `Year` dimension with 2019 and 2024 categories, and `table` as the visualization type. Its printed caption and source are outside the crop, but that observation does not establish why the model returned a null title. The table illustrates missing title metadata alongside useful descriptions; the figure illustrates a questionable inference from an axis label. Inspecting each crop alongside its JSON distinguishes an unpopulated field from a populated field that misinterprets visible text.

## Implementation options

The top-level Python `extract_metadata(image_path, config_path=...)` returns an `ExtractionResult` with diagnostics, response status, usage when returned, and validated metadata. A custom config path is supported there even though the CLI chooses packaged presets. The schema's version is exported schema metadata and is not required in individual records.

## Common mistakes

- Substituting the existing human-reviewed gold chart record would hide the production crop and model behavior.
- Equating schema validation with factual verification leaves interpretation errors undetected.
- Filling image-invisible context from the PDF without labelling the intervention breaks the stated evidence boundary.

## Verification

- Match each selected PNG to a JSON file with exactly the same stem in the metadata directory. The recorded exercise has two selected-image responses; the remaining detector candidates intentionally have no metadata.
- Run `inspect_metadata.py` on each downloaded JSON. A zero exit status and a display of populated fields indicate that the record satisfies the canonical model; the script should leave the input file unchanged.
- Compare the figure response with the crop. Confirm that `title` contains the axis label `Percent of population` and retain this finding for the review in chapter 5.
