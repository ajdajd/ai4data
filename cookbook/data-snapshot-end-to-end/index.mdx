# Practical Guide to the Data Snapshot End-to-End Workflow

**A cookbook for developers and data curators working with institutional PDFs.** Version 0.1 (working draft), October 2026.

:::note[Working draft]
This guide is working material of the AI for Data – Data for AI program. It does not represent official World Bank Group guidance or policy. The [contributing page](./contributing.md) explains how to report corrections and propose reviewed examples.
:::

Institutional reports contain charts, tables, maps, and monitoring summaries whose analytical meaning depends on their visual structure. A data snapshot preserves a bounded analytical region as an image. The production `ai4data.data_snapshot` workflow detects candidate regions and can describe their visible content with structured semantic metadata.

This guide follows the practical questions involved in preparing a PDF, selecting models, extracting crops, generating metadata, and reviewing the files. It then explains combined execution, recovery, and proposed improvements. Its executed example uses the Shona policy brief, DocLayout-YOLO, and separate metadata requests for one figure and one table.

The result is a set of PNG images and Schema v1.4 JSON descriptions. Numerical transcription, publication, search, and other downstream processing are possible next steps, covered separately by the [Extracting Data from Documents cookbook](/cookbook/data-from-documents/). This guide is self-contained for the production snapshot workflow and does not require completing that cookbook first.

## Prerequisites

- Python 3.11 or later, an isolated environment, and a checkout of the repository are available.
- A developer can install optional dependencies and run commands; a curator can inspect institutional charts and tables.
- The Shona source PDF is downloaded from its publisher following [chapter 1](./preparation.mdx).
- Metadata execution requires an authorized provider key and credits. Snapshot-only execution does not require that key.

## First steps

1. Prepare the source and environment in [chapter 1](./preparation.mdx). Allow about thirty minutes plus installation time.
2. Choose the detector and device in [chapter 2](./models.mdx), then inspect the snapshot run in [chapter 3](./snapshots.mdx). Allow about thirty minutes plus machine-dependent execution time.
3. Generate metadata for the two selected images in [chapter 4](./metadata.mdx), then review the source and outputs in [chapter 6](./review.mdx). Allow about one hour plus provider waiting time.

The later chapters explain combined execution, recovery, and proposed improvements. These are indicative learning times. Inference performance was not benchmarked.

## Running example

The guide uses the real *From Stateless to Citizens: The Journey of Shona in Kenya* policy brief. The [ReliefWeb report](https://reliefweb.int/report/kenya/policy-brief-stateless-citizens-journey-shona-community-kenya) links to the [PDF attachment](https://reliefweb.int/attachments/831aca28-6777-4cb9-9b84-8976c63061fb/Policy%20Brief%20on%20Shona%20community_From%20Stateless%20to%20Citizens.pdf). PDF page 4 contains both selected artifacts. Their numerical observations remain source content. No numerical transcription was performed for this guide.

The recorded detector output contains seven figure-labelled crops and one table-labelled crop, including an irrelevant photograph. The selected chart is `figure_001`; the existing gold dataset uses `figure_000` for a different extraction history. Filenames identify different extraction histories; they are not interchangeable identifiers for reviewed metadata.

## Scope of the examples

The figure and table crops are actual production outputs; their metadata records come from separate selected-image requests. The combined example is unexecuted and its file tree is explicitly conditional. Other detectors are documented but not benchmarked here. The second-stage classifier and improvement roadmap are proposed extensions. The example was run on 30 October 2026 using DocLayout-YOLO 0.0.4, CPU, 300 DPI, and the unchanged packaged OpenRouter preset. The two JSON files are unedited model responses, with review findings in chapters 4 and 6.
