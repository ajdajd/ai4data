# 5. Combined execution and output structure

**Question:** How are both stages invoked together?

## Rationale

The separate stages in chapters 2 to 4 show how to select data snapshots, inspect metadata, and review the results before choosing a wider request scope. The combined command first extracts data snapshots and then requests metadata for the newly extracted images. It is convenient once the input, detector, provider, and review process are understood. It is also less selective than the two-image exercise: all newly detected regions are sent to metadata extraction.

The combined example here is supported by the implementation but deliberately unexecuted. Its directory tree illustrates expected naming and stage relationships. The recorded evidence in this guide comes from snapshot-only extraction and the two selected metadata-only requests.

## Target state

- The reader can identify the combined entry point and its cost implications.
- Expected combined output is distinguished from recorded example artifacts.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | The organization completes snapshot and metadata extraction as separate steps and can match each selected image to its description. |
| **AI-ready** | A developer can configure the combined entry point, identify its output pairs, and account for metadata requests across all newly extracted candidates. |
| **AI-native** | An organization integrates both stages with monitored request volume, output checks, and human review. The combined command alone does not provide that wider operational system. |

:::info[Running example]
For the sample PDF used in the tutorial, the combined invocation specifies a fresh `output/shona-combined` root and is not executed for this guide. Its abbreviated tree shows where the already familiar chart and table pairs would appear if extraction and metadata requests succeeded.
:::

## Recipes

<Recipe title="5.1 Prepare a combined invocation" level="AI-ready" skills="Developer and data curator" time="Ten minutes to prepare the optional invocation; execution time varies">

**Result:** The reader has a supported command and a fresh destination.

A fresh destination matters because PDF-level skip logic applies before metadata extraction. The following invocation is an instruction for readers; it was not executed for the cookbook.

```bash
python -m ai4data.data_snapshot \
  --input=data/policy_brief_on_shona_community_from_stateless_to_citizens.pdf \
  --output-dir=output/shona-combined --model=doclayoutyolo --device=cpu \
  --metadata-provider=openrouter
```

1. Confirm that the source can be sent as extracted images to the provider and that the number of candidate images is acceptable.
2. Use a new output root and record the configuration. GPU selection changes local detection. The provider operates the metadata service.
3. After execution, check every saved data snapshot and metadata record. A detector false positive can also incur a metadata request.

**Worked example.** The guide does not execute this command. If a run reproduces the observed eight candidate images and every metadata request succeeds, the output would have eight PNGs and eight JSONs, including a record for the photograph. This is a conditional expectation; only the selected two-image requests were performed.

**What this does not do.** The combined command does not roll back an entire run after failure. Extraction errors can prevent metadata processing; metadata errors stop at the failing image while earlier files remain.

</Recipe>

<Recipe title="5.2 Read the expected directory layout" level="AI-ready" skills="Developer and data curator" time="Ten minutes to interpret the expected file layout">

**Result:** The relationship between data snapshot and metadata filenames is explicit.

The expected structure below is abbreviated to the two target artifacts. Other detections would also appear. The observed data snapshot filenames are used, but the complete combined result has not been generated.

```text
output/shona-combined/doclayoutyolo/
├── snapshots/
│   ├── policy_brief_on_shona_community_from_stateless_to_citizens_figure_001.png
│   └── policy_brief_on_shona_community_from_stateless_to_citizens_table_000.png
└── metadata/
    ├── policy_brief_on_shona_community_from_stateless_to_citizens_figure_001.json
    └── policy_brief_on_shona_community_from_stateless_to_citizens_table_000.json
```

1. Match files by their complete stems because source names can contain underscores.
2. Inspect missing JSON as a possible incomplete metadata stage. The PNG may still be valid.
3. Page coordinates and provider usage logs are not written in this tree.

**Worked example.** The actual staged exercise has all eight detector outputs in the local run directory but metadata for only the selected chart and table. The downloadable folder contains those selected pairs, the source-page image, and the inspection helper. Neither folder is claimed to be a complete combined run.

**What this does not do.** A directory tree is a format illustration. It does not establish detection coverage, metadata completeness, or successful execution.

</Recipe>

## Implementation options

Python callers can use `run_pipeline(input_path, output_dir, model_name="doclayoutyolo", device="cpu", metadata_provider="openrouter")`. It returns new snapshot paths followed by metadata paths. A fully skipped PDF command returns no new paths. Use the separate commands when a curator needs to select data snapshots before incurring metadata costs.

## Common mistakes

- Running combined execution after snapshot-only in the same root skips the PDF and leaves missing JSON unfilled.
- Treating a schematic tree as recorded output invents evidence.
- Expecting a combined run to filter out photographs adds a stage that does not exist.

## Verification

- Compare the proposed command with the staged example. Its destination should be `output/shona-combined`, distinct from `output/cookbook-data-snapshot`, so the prior data snapshots would not trigger PDF-level skipping.
- Read the expected tree by matching complete PNG and JSON stems. It should illustrate the selected pairs while leaving clear that other newly detected regions would also be processed.
- If the command is run later, inspect its actual files and failures before describing it as successful. The current tree remains an unexecuted illustration.
