# 3. Snapshot extraction

**Question:** How are figures and tables extracted as images?

## Rationale

PDF pages are rendered as RGB images before the detector runs. The detector returns a class, confidence, and normalized rectangle for each retained region. Normalized coordinates describe the left, top, right, and bottom edges as fractions of page width and height, measured from the top-left corner.

The production workflow crops these rectangles directly. It does not pad boxes, merge panels, or persist page coordinates. The semantic JSON generated in the next stage describes image content and serves a different purpose.

## Target state

- The snapshot-only command saves inspectable PNG files.
- The curator can distinguish the target chart and table from irrelevant detections.

## Maturity levels

| Level | Steps |
|---|---|
| **Foundational** | A curator inspects the source page and records the evidence and unresolved questions. |
| **AI-ready** | A developer runs the documented stage and checks its files against the source and schema. |
| **AI-native** | The organization proposes monitored automation with retained evidence and human review. This level describes an operational goal. The available package features are documented separately. |

## Recipes

<Recipe title="3.1 Run snapshot-only extraction" level="AI-ready" skills="Developer and data curator" time="Twenty minutes plus execution and review">

**Result:** The document has been processed without a metadata API request.

The following command uses the PDF acquired in chapter 1. `--output-dir` is the root; the package appends the detector name and `snapshots/`. It renders at 300 DPI by default. All twelve pages are processed because the CLI has no page-range option.

```bash
python -m ai4data.data_snapshot.extract_data_snapshot \
  --input=data/policy_brief_on_shona_community_from_stateless_to_citizens.pdf \
  --output-dir=output/cookbook-shona --model=doclayoutyolo --device=cpu
```

1. Use a fresh destination so that an earlier file does not cause the entire PDF to be skipped.
2. Run the command and inspect progress and printed paths. An input can also be a directory searched recursively for PDFs.
3. Keep source filename stems unique across a directory run, including subdirectories; outputs are flattened into one model directory.
4. Open the saved crops before sending any to a metadata provider.

**Worked example.** The recorded run saved `figure_000.png` through `figure_006.png` and `table_000.png`, each prefixed by the complete PDF stem. `figure_000` is the cover photograph, `figure_001` is the chart on PDF page 4, and `table_000` is the demographic table on that same page. These counts describe saved detector outputs; the photograph demonstrates why human review is still needed.

**What this does not do.** This command does not generate metadata or persist page coordinates, confidence scores, page images, or a quality report. No OCR stage is performed.

</Recipe>

The figure counter and table counter are independent and start at zero. They continue across the document, so the printed Figure 1 can have the filename suffix `figure_001`. The index does not encode a page number or the printed caption.

1. Open the [source page](pathname:///cookbook-files/data-snapshot-end-to-end/shona-page-4.webp), the [figure crop](pathname:///cookbook-files/data-snapshot-end-to-end/policy_brief_on_shona_community_from_stateless_to_citizens_figure_001.png), and the [table crop](pathname:///cookbook-files/data-snapshot-end-to-end/policy_brief_on_shona_community_from_stateless_to_citizens_table_000.png).

**Worked example.** Both selected crops retain their main analytical content but exclude their printed captions and source notes. This is a useful limitation: a later metadata model receives the crop only and cannot be expected to recover those excluded details.

## Implementation options

Use `--dpi` to choose a positive rendering resolution and a new output root to compare settings safely. Higher resolution consumes more rendering memory and storage; inference also uses the adapter's own image-size setting. The lower-level `extract_snapshots` API accepts a custom detector, while `run_extraction` provides the model-scoped directory convention.

## Common mistakes

- Reading the filename index as a printed figure number points to the wrong artifact.
- Counting every figure-labelled crop as analytical content hides false positives.
- Assuming captions are automatically included can make metadata incomplete.

## Verification

- The selected figure and table are visually matched to PDF page 4.
- The source page, captions, legends, and missing context have been checked.
- The snapshot-only run has made no metadata request.
